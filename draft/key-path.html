鍵盤路徑勘查

在真正的登記頁上按一下，它會把整頁的 Tab 順序標出來，告訴你「Tab 幾次會到登記鍵」。它不點任何東西，只告訴你路怎麼走。

安裝

⌨︎ 鍵盤路徑勘查
把左邊這顆按鈕拖到書籤列就裝好了。書籤列沒開的話按 ⇧ ⌘ B。
拖不動？改用手動新增，或看它到底做了什麼

Chrome 選單 → 書籤 → 書籤管理員 → 右上角三點 → 新增書籤，名稱隨便填，網址貼下面複製到的那一長串。

活動前先勘查一次

  1. 登入後打開登記頁
    要用你實戰時會用的那個瀏覽器和那個帳號，因為登入狀態會改變頁面上的元素數量，Tab 號碼跟著變。
  2. 點書籤列上的「鍵盤路徑勘查」
    頁面上每個 Tab 到得了的元素會冒出一個號碼，右上角出現控制面板。紅色號碼是它猜的登記／送出鍵。
  3. 選定目標
    點目標的號碼，或用面板上「可能的目標」的快捷鈕。面板會給你一行 Tab × N。
  4. 當場驗證一次
    在頁面空白處點一下把焦點清掉，按 N 次 Tab，看焦點是不是真的停在登記鍵上（面板會即時顯示你現在在第幾個）。護欄預設開著，這時候按 Enter 不會真的送出。
  5. 把數字記下來
    寫進倒數器的活動備註，或直接記在紙上。這個數字才是你實戰要用的東西。
如果登記鍵在活動開放前根本不存在，勘查會掃不到它。這時候先勘查到「最接近的那個穩定元素」（例如同意條款的勾選框），實戰開放後按一次「重新掃描」再補上剩下幾次 Tab——或直接在開放後的頭幾秒重掃，通常還來得及。

活動當天

  1. 開好登記頁，開好倒數器
    倒數器用浮動視窗壓在登記頁上方，這樣不用切分頁。
  2. 在頁面空白處點一下
    這一步是把焦點歸零，Tab 才會從第 1 個開始數。網址列點過就不算，一定要點頁面本身的空白區。
  3. 發令時 Tab × N，然後 Enter
    手不用離開鍵盤，也不用瞄準。Tab 連按可以按很快，這一段通常在 100 毫秒內結束。
  4. 後面每一步同樣用鍵盤
    確認視窗跳出來通常 Tab 一兩次就到確定鍵。這一步也值得先勘查。

幾件要先知道的事

  • 號碼會變。頁面內容一改（跳出橫幅、載入推薦商品、活動開放），Tab 順序就變了。所以勘查要盡量貼近實戰狀態，開放後也值得重掃一次。
  • iframe 裡的東西數不到。面板會告訴你頁面上有幾個 iframe。如果登記表單在 iframe 裡，Tab 進去之後的計數要另外算——那種情況勘查完進去再數一次。
  • 護欄不是萬能。它擋 Enter、Space 和點擊落在送出類按鈕上的情況，但擋不掉網站自己用 JavaScript 觸發的送出。演練時還是別在真的能成立的活動上亂按。
  • 它不會替你點。沒有自動點擊、沒有排程送出、不讀也不送任何表單資料。所有東西都在你的瀏覽器裡跑完，不連任何伺服器。
配套工具：搶登記發射台（毫秒級發令倒數）。兩個一起用——倒數器解決「什麼時候按」，這個解決「按下去之後手要往哪走」。
